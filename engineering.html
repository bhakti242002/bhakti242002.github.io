Insight Bridge

A full-stack web app that turns any uploaded spreadsheet into a working dashboard, with no setup.

Python, Flask, React, Claude API, Recharts, Supabase

Try it live View code

Turning a spreadsheet into a dashboard usually means templates, manual chart picking, and guessing what each column means from its name.

Key decisions

  • AI suggests, code computes

    Claude proposes clean labels and translates plain-English questions, but every figure on screen comes from deterministic code, so a wrong suggestion can’t produce a wrong number.

  • It still works without AI

    If the AI service goes down, the dashboard still renders with the original column names. Try turning the AI off above.

  • The user has the last word

    Statistical type inference classifies each column as a date, total, average, category, ID or free text, and any correction the user makes overrides it.

  • Fix the slow path

    One bottleneck dominated runtime. Fixing it took a 10,000+ row file from 36 seconds to 150 milliseconds.

The test datasets are unrelated real-world files, from sales to student grades. Questions are answered as single-step lookups, not multi-step reasoning.

AI SQL Auditor

An evaluation harness that checks whether Claude’s SQL rewrites actually make queries faster.

Python, PostgreSQL, EXPLAIN ANALYZE, Claude API, Power BI

View code

AI assistants suggest SQL optimizations constantly. Almost nobody checks whether they’re right, so I measured 120 of them.

What I found

  • Measured, not trusted

    A rewrite only counts as an improvement when EXPLAIN ANALYZE shows it is faster.

  • It never left a query alone

    Claude flagged an issue in all 120 queries.

  • The pattern matters

    It was near-perfect on correlated subqueries and consistently made OR conditions worse.

  • Reproducible by design

    Synthetic data on a TPC-H-style schema with 8 tables and about 80K rows keeps execution plans stable. A real-world dbt sample is reviewed separately and kept out of the core numbers.

Results, 120 rewrites

Helped38%
No change34%
Ran slower20%
Failed to run8%

In other words, 62% of Claude’s rewrites didn’t make the query faster.

Live Revenue Risk Check

A deployed API: type a public company’s ticker and get a live probability that its revenue declines next year.

Python, scikit-learn, Random Forest, SEC EDGAR API, Vercel serverless

Try it live View code

Predicting a company’s revenue a year out is hard, and most portfolio models are judged on shuffled data that quietly leaks the future. I wanted something honest that runs on live data, not a frozen notebook.

Key decisions

  • No peeking at the future

    The model is trained on 2009 to 2020 and tested only on 2021 onward, so its score reflects years it never saw.

  • Live, not frozen

    Revenue, assets, liabilities and net income come from data.sec.gov on every request, then get rebuilt into 4 features: revenue scale, debt-to-assets, net margin and year-over-year growth.

  • Missing data stays visible

    Missing XBRL tags are handled with missingness indicators rather than being hidden.

  • Honest about the sample

    505 company-years across 48 large, well-known companies is a small, non-random sample, and the share of declines shifted from 33% in training to 22% in testing.

Results

ROC-AUC on unseen years0.62
Real declines caught50%
Caught by a naive baseline0%
Company-years505

A naive “no decline” model looks 78% accurate but catches none of the declines. An ROC-AUC of 0.5 is chance level.
